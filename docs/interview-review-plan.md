# 本地测试版总结与实习面试复习计划

2026-11-07用户确认：本地测试版暂时收尾；prompt15–26全部留到下一版本。当前目标是能独立解释、定位、修改和验证已有项目，准备中大厂Go/后端实习面试（包括哔哩哔哩等目标公司），不把泛化练习当成某家公司的真实题库或录用保证。

## 复习顺序

|单元|内容|交付与自测标准|
|---|---|---|
|1 项目全貌|业务边界、架构、问答/工单/更新三条主链|脱稿讲90秒，画出组件及权威数据位置，能区分真实依赖和夹具|
|2 Go与HTTP|context、goroutine/channel、error、超时、SSE、关闭|沿一次请求定位入口及退出点，解释取消和提交结果不确定性的区别|
|3 MySQL与幂等|事务、行锁、唯一约束、版本冲突、确认签名|解释同操作Key重放如何收敛、不同Key为什么不保证去重、工单成功消息失败如何恢复|
|4 Kafka与索引一致性|Outbox/Inbox、offset、重试、generation/epoch|画出发送成功但回执丢失、单索引失败、旧任务迟到的处理时序|
|5 检索与AI边界|BM25/向量、RRF、MySQL复核、引用、工具预算|解释分数不可直接相加、旧规则过滤局限、引用合法不等于回答一定正确|
|6 部署与观测|镜像、探针、资源、HPA、指标、故障证据|解释readiness与liveness、分区限制、合成CPU扩容不证明吞吐增长|
|7 简历与模拟面试|项目表达、追问、故障复盘、诚实边界|简历每条有代码/测试证据；完成一轮问答后按遗漏概念补练|

并行基础线：Go语言与并发、计算机网络、MySQL索引/事务、Redis一致性与缓存、Linux排障；算法按数组/哈希、双指针、栈队列、链表、树、二分、图和基础动态规划循序练习。每次先独立写并口述复杂度，再复盘；不以刷题数量代替理解。不预设每天时长、投递日期或公司岗位要求。

## 第一单元：三条主链

问答：浏览器→Nginx→API认证/会话→Agent规划工具→ES与Milvus召回/RRF→MySQL当前状态复核→模型生成→引用校验→SSE与消息保存。检索层解决候选召回，数据库解决当前有效性，生成层解释证据；任何一层都不能单独保证回答正确。

工单：模型准备提案→服务端签名确认→页面明确确认→不经模型的确定性执行→事务与原操作Key幂等→记录业务结果→保存消息。业务提交和消息保存是两个事实，断线不等于回滚。NoAppealPolicies只能支持已定义的本地人工复核边界，不证明平台资格。

更新：管理员修订/核验/发布→事务内Outbox→relay投Kafka→Inbox持久化→Worker构建私有代际→两侧manifest校验→MySQL选择活动目标→查询使用新代际。处理重复与旧任务，不能描述成跨数据库和消息系统的单一事务。

首轮口述问题：
1. 这个项目为谁解决什么问题？哪些事明确不能做？
2. 为什么ES和Milvus已经返回结果，还需要查询MySQL？
3. 工单已经提交，但浏览器断线时，系统如何避免误判并重复提交？

下一次反馈以你的实际回答为准，逐项补足原理和代码定位；不要求背诵助手的标准答案。先复习，不开始下一版本功能。
